# Production-Grade Medical RAG Chatbot

A high-precision, production-grade Retrieval-Augmented Generation (RAG) medical chatbot designed for clinical and health information assistance. The system combines high-density vector recall with cross-encoder re-ranking and strict clinical guardrails to deliver sub-second, zero-hallucination responses grounded strictly in authoritative medical literature.

The architecture is built around a **Single Source of Truth** pattern using **Supabase (`pgvector`)** with **HNSW indexing** for candidate recall and raw document chunk storage, paired with **Groq (`llama3-8b-8192`)** for ultra-low latency inference.

- **Two-Stage Retrieval Pipeline:** Vector candidate recall ($K=10$) via `BAAI/bge-m3` paired with Cross-Encoder re-ranking ($K=3$) via `BAAI/bge-reranker-v2-m3`.
- **Single Source of Truth Architecture:** Metadata, 1024-dimensional dense vectors, and full chunk text are stored together in Supabase Postgres, eliminating redundant cache layers and synchronization issues.
- **Sentence-Boundary Preservation:** Markdown header-aware splitting coupled with dangling-sentence cleaning (`clean_chunk_text()`) to eliminate truncated clinical contexts.
- **Query Embedding Caching:** SHA-256 query hashing with Supabase-backed vector caching (`query_embeddings`) to minimize duplicate embedding computation.
- **High-Performance Inference:** Powered by Groq's fast Llama 3 engine (`llama3-8b-8192`) operating at a low temperature ($0.2$) for factual clinical grounding.
- **Automated Process Lifecycle:** Master process manager (`run.py`) handles port cleanup, background backend deployment, health-check verification, and interactive terminal launch.

## Features

- **Header-Aware Knowledge Chunking:** Markdown files are parsed along structural section headers (`H1`, `H2`, `H3`), merging placeholder sub-sections and preserving sentence completeness.
- **Dense Vector Search:** 1024-dimensional vector embeddings generated by `BAAI/bge-m3` stored in Supabase with HNSW Cosine Indexing.
- **Cross-Encoder Re-Ranking:** Top-10 vector candidates are re-evaluated using joint attention (`BAAI/bge-reranker-v2-m3`) to filter for the top-3 highest-relevance context blocks.
- **Query Vector Caching:** Automatically hashes user inputs (SHA-256) and stores pre-computed embeddings in Supabase (`query_embeddings`).
- **Clinical Safety Rules:** Strict system prompts direct the LLM to explicitly state when provided medical documents lack sufficient detail, preventing hallucinated medical guidance.
- **Integrated Terminal Interface:** Interactive CLI client (`term_client.py`) with rich terminal formatting and context source metadata display.

```
 └───────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
          (1024-dim Vectors + Full Chunk Text + Section Metadata)
                                     │
                                     ▼
                        ┌──────────────────────────┐
                        │     Supabase Postgres    │
                        │   (document_chunks)      │
                        └──────────────────────────┘


========================================================================================
                           STAGE 2: QUERY & RETRIEVAL PIPELINE
========================================================================================

 [ User Query ] ("What is the treatment for chloroquine-resistant malaria?")
             │
             ▼
 [ Query Cache Check ] ──(Match Found?)──> [ Retrieve Cached Vector ]
             │ (Miss)                                │
             ▼                                       │
 [ BAAI/bge-m3 Model ] (Generates 1024-dim Vector) ─┘
             │
             ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │  1. CANDIDATE RECALL (Supabase HNSW Vector Search)                      │
 │     - Query Vector matched against document_chunks                      │
 │     - Fetches Top 10 Candidate Chunks directly with raw text           │
 └───────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │  2. CROSS-ENCODER RE-RANKING (BAAI/bge-reranker-v2-m3)                  │
 │     - Scores (Query, Raw Text) pairs using joint cross-attention       │
 │     - Selects Top 3 Chunks with highest semantic relevance             │
 └───────────────────────────────────┬────────────────────────────────────┘
                                     │
                                     ▼
 ┌────────────────────────────────────────────────────────────────────────┐
 │  3. LLM GENERATION & INFERENCE (Groq llama3-8b-8192)                    │
 │     - Combines System Prompt + Top 3 Context Chunks + User Question    │
 │     - Generates grounded, clinically guarded response                  │
 └───────────────────────────────────┴────────────────────────────────────┘
```

## Database Setup (Supabase SQL)

Execute the following DDL script inside your **Supabase SQL Editor** to initialize the required extensions, tables, vector indexes, and RPC functions:

```sql
-- Enable the vector extension
CREATE EXTENSION IF NOT EXISTS vector;

-- Create Document Chunks Table
CREATE TABLE IF NOT EXISTS document_chunks (
  id TEXT PRIMARY KEY,
  document_id TEXT NOT NULL,
  section_title TEXT,
  subsection_title TEXT,
  text TEXT NOT NULL,
  embedding vector(1024)
);

-- Create Query Vector Cache Table
CREATE TABLE IF NOT EXISTS query_embeddings (
  query_hash TEXT PRIMARY KEY,
  embedding JSONB NOT NULL,
  created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

-- Create HNSW Index for Fast Cosine Vector Search
CREATE INDEX IF NOT EXISTS document_chunks_embedding_hnsw_idx 
ON document_chunks 
USING hnsw (embedding vector_cosine_ops);

-- Candidate Recall RPC Function
CREATE OR REPLACE FUNCTION match_document_chunks (
  query_embedding vector(1024),
  match_threshold float,
  match_count int
)
RETURNS TABLE (
  id text,
  document_id text,
  section_title text,
  subsection_title text,
  similarity float,
  text text
)
LANGUAGE sql STABLE
AS $$
  SELECT
    document_chunks.id,
    document_chunks.document_id,
    document_chunks.section_title,
    document_chunks.subsection_title,
    1 - (document_chunks.embedding <=> query_embedding) AS similarity,
    document_chunks.text
  FROM document_chunks
  WHERE 1 - (document_chunks.embedding <=> query_embedding) > match_threshold
  ORDER BY document_chunks.embedding <=> query_embedding
  LIMIT match_count;
$$;
```

## Knowledge Base Ingestion

Place your clinical Markdown files inside the `./knowledge_base/` folder and execute the ingestion pipeline:

```bash
python ingestion.py ./knowledge_base
```

### Pipeline Actions:
1. Parses markdown document metadata headers (`<!-- DOCUMENT_METADATA ... -->`).
2. Splits documents by structural header levels (`#`, `##`, `###`).
3. Cleans incomplete sentence boundaries and merges low-value placeholder subsections.
4. Prepends contextual breadcrumbs (e.g., `[Disease: Malaria | Section: Treatment]`).
5. Embeds chunks with `BAAI/bge-m3` (1024-dim) and upserts metadata, vectors, and raw text into Supabase.

## Running the Application

Launch the full system (FastAPI server + interactive CLI client) using the orchestrator:

```bash
python run.py
```

`run.py` performs the following automated steps:
1. Checks port `8000` and clears stale processes.
2. Spawns the FastAPI server background process (`main_server.py`).
3. Polls the health check endpoint (`http://127.0.0.1:8000/`) until ready.
4. Launches the interactive command-line terminal interface (`term_client.py`).
5. Handles clean teardown of child processes upon termination (`quit` or `Ctrl+C`).

## Key Design Decisions

1. **Single Source of Truth Storage:** By storing raw text alongside embeddings in Supabase (`document_chunks.text`), external index synchronization bugs and high memory overhead from secondary vector databases are eliminated.
2. **Sentence Boundary Preservation:** The `clean_chunk_text()` sanitizer ensures that text splitting never clips words or dangling sentences, maintaining full semantic clarity for clinical information.
3. **Two-Stage Accuracy:** Vector search handles scalable candidate filtering ($K=10$), while the Cross-Encoder re-ranker evaluates token-level interactions ($K=3$), preventing context dilution in the LLM.
4. **Embedding Caching:** Standard queries utilize SHA-256 pre-computed embedding caches in `query_embeddings`, reducing embedding compute latencies.

## Troubleshooting

| Issue | Cause | Resolution |
|---|---|---|
| `ERROR: 42703: column document_chunks.text does not exist` | Database schema missing `text` column | Run `ALTER TABLE document_chunks ADD COLUMN IF NOT EXISTS text TEXT;` in Supabase SQL Editor. |
| `GROQ_API_KEY environment variable missing` | Missing or invalid `.env` file | Add `GROQ_API_KEY=gsk_your_key` to your `.env` configuration file. |
| Bot answers *"I don't have enough verified information"* | Empty database vector table | Ingest knowledge base files by running `python ingest_knowledge_base.py ./knowledge_base`. |
| Port 8000 already in use | Stale Uvicorn server running | `run.py` automatically terminates existing processes on port 8000 using `lsof`/`fuser`. |
